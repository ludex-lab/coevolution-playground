# experiments/2026-11-15

- [mb-conversation-loss-oracle](mb-conversation-loss-oracle/): Schema-valid is not conversation-preserving: on frozen synthetic translations of tool-using chat requests from one toy LLM API dialect to another, a model-free rule oracle over a shared intermediate record flags every planted avoidable loss or injection (dropped, altered or needlessly demoted system text, role swap, same- and cross-role merges, reordered, dropped or injected messages, stripped or injected tool-error flags, renamed tool calls, altered arguments or results, dropped or injected tool definitions, injected thinking budget, dropped or altered controls) with its rule id and field path, while a toy static target-schema check passes every one of them; encoding-only changes (role-field rename, list result joined as declared, key order, re-minted call ids, omitted default error flag) do not alarm, except a stripped trailing newline that is reported as a false alarm, and changes the declared target limits force are labelled forced, not faults; agrees with an independent oracle on every fixture and exhaustively on short conversations (Soft method sketch of [arXiv 2611.15543](https://arxiv.org/abs/2611.15543); not a reproduction)
- [w24-threshold-compliance](w24-threshold-compliance/): **Top**: a high abstention rate is not threshold compliance: on synthetic 32-item batches with caller-labelled probabilities and stated thresholds 0.5, 0.75 and 0.9 (answer iff p > t, a tie abstains), a known-p audit flags all five planted policies (format-only, inverted, constant answered set, rate-matched wrong items, one non-nested item) and passes both compliant controls, including one where no probability lies in (0.75, 0.9] so an unchanged answered set is not a fault; a belief-free audit that sees only decisions flags the inverted and non-nested policies as INCONSISTENT and never says COMPLIANT, while an abstention-rate-only evaluator certifies four of the five faults; a missing threshold run or absent probabilities is REJECT on_unmeasured; agrees with an independent oracle on every fixture and exhaustively on small batches (Top method sketch of [arXiv 2611.14661](https://arxiv.org/abs/2611.14661); not a reproduction)
- [w24-trust-needs-feedback](w24-trust-needs-feedback/): **Top**: trust in an advisor needs timely external feedback: on synthetic 10-round sessions with a helpful, an unhelpful and a mixed advisor (right in 10, 0 and 5 of 10 rounds) and a declared untrusted prior, trust rises only on feedback from a declared external source that names the session's advisor and a real, already-given round no more than max_age rounds old, and one accepted "incorrect" drops it within one round; with feedback the helpful advisor alone is upgraded, without feedback none is (the helpful advisor staying untrusted is a declared cost), eight planted spoofs (self-sourced, str-subclass source, colliding source key, stale, other advisor, future round, confident self-claim, undeclared source) are all refused, a persuadable baseline that starts high and rises with stated confidence still relies on the unhelpful advisor at the end without feedback, 0/3 false alarms on controls (including feedback exactly max_age old), and a pending decision past its deadline resolves to its declared on_expiry (DENY, SAFE_FALLBACK, ESCALATE or HOLD), never RELY; agrees with an independent oracle on every valid fixture and exhaustively on short sessions (Top method sketch of [arXiv 2611.14833](https://arxiv.org/abs/2611.14833); not a reproduction)
- [w24-alert-silence-is-not-fix](w24-alert-silence-is-not-fix/): **Top**: a disappearing alert is not a fix: a toy taint analyzer over a tiny IR has one declared modelling gap (its parse_url model taints a URL's query but not its path), and a separate pure-Python executor runs each program on a concrete exploit input and reports whether the exploit reaches a sink; on eight vulnerability-preserving rewrites in four families (flow through the un-propagated field, helper, container detour, split concatenation) that silence the alert, the "alert gone means fixed" baseline issues a fixed receipt for every one while the gate, which issues fixed only when the executor's result for the exact rewritten program and exploit says the exploit no longer reaches the sink, refuses every one as alert_silenced_vuln_present; three refactor-only controls get no receipt, three true fixes are all accepted, a missing or unbound executor result is refused as on_unmeasured, and detection and rewrite robustness are reported side by side; agrees with an independent oracle on every valid fixture and exhaustively on short programs (Top method sketch of [arXiv 2611.17123](https://arxiv.org/abs/2611.17123); not a reproduction)
